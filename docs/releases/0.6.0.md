# WIND 0.6.0

This release introduces the canonical `wind_tracking_v1` protocol and 17
source-specified algorithms. It deliberately breaks algorithm-name and optimizer
interface compatibility. Historical runs belong to their archived source version.

## Algorithms and interfaces

Nesterov now evaluates the gradient at the extrapolated point. AdamW applies
decoupled decay, AMSGrad uses raw moments and their second-moment maximum,
and PolyakRuppertSGD keeps the raw SGD trajectory separate from its average.
All four ZO methods use fresh symmetric pairs. ExponentiatedGradient preserves
zero support without imposing a positive floor. Gaussian QR frame generation
corrects column signs to obtain Haar-distributed frames.

The active catalog no longer accepts historical algorithm aliases. Old optimizer
imports from `experiment`, `optimizer_compat`, `optimizers_extra`, or `manifold`
are not supported. Import algorithms through `catalog.create_optimizer` or
`optimizers`. The old sources remain in `legacy/pre_060_*` archives.
The ambiguous `manifold.geodesic_distance` alias is also retired; the explicit
Grassmann and canonical Stiefel distance functions remain separate.

Custom algorithms implement `initialize(x0, rng, task_spec)` and `advance(client)`
and return `AdvanceResult`. There is no implicit initial observation. An
incomplete ZO batch spends its actual calls, retains the previous recommendation,
and does not increment the completed-update count. Ordinary runs keep the target
fixed within an update; canonical runs advance after every query. These clocks
are distinct and explicitly reported.

## Protocol and reporting

Configuration and export schema 3 are required. Configurations without an
explicit version are not silently interpreted as corrected implementations.
The mathematical `metrics_v2` and API isolation `local_series_v2` contracts remain
in effect. Observation and Gym information do not contain evaluator truth;
completed-series release, terminal abort, and idempotent close remain enforced.

The canonical suite has 32 tasks, 20 development seeds, 50 evaluation seeds and
4000 queries per compatible configuration. It reports queried-point scores;
recommended positions are retained separately. Fixed references do not depend
on the order of supplied algorithms. Changes to the task protocol produce a
custom study, not a canonical result.

The five mechanistic studies use `paper_tracking_v3`. The RL protocol
`rl_transfer_v3` compares online Q-learning and Stable-Baselines3 2.9.2 PPO with
replicated training and crossed training-seed/workload uncertainty. Full runs
save numerical data and policies without generating article figures.

## Reproduction

Reproduce a result with its complete source snapshot, Python and dependency
lock, seed streams, task specification and parameters. A display label alone
does not identify an implementation. New starts, algorithms, stream namespaces
and the Haar generator intentionally change some numbers. They are not required
to reproduce historical errors. Old results and manuscript files are not
automatically modified or relabelled.
