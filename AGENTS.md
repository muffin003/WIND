# Agent Instructions for WIND

## Project hygiene and temporary files

Keep the project free of disposable artifacts without losing user work,
experiment results, or evidence needed for reproducibility. These rules apply
to files created during your task; they do not authorize a general cleanup of
pre-existing files.

### Before creating files

- Inspect the existing workspace state and preserve unrelated changes made by
  the user or other agents. Do not assume the worktree starts clean.
- Put agent-created disposable scripts, scratch files, intermediate outputs,
  and temporary logs in `local/tmp/<unique-task-id>/`. Do not scatter them in
  the repository root, `src/`, `tests/`, or published result directories.
- Keep track of the temporary paths you create. Do not adopt an existing
  directory belonging to another task or process as your scratch directory.
- Avoid extra reports, summaries, backup copies, and helper scripts unless
  requested or necessary for the task. Reuse established project tooling.
- For Python scratch work, prefer scoped temporary directories with automatic
  cleanup where practical. Do not store durable outputs in such directories.

### Materials that must be preserved

- Experiment results, figures, selected parameters, manifests, regression
  fixtures, and other reproducibility materials are not disposable scratch
  files, even when generated by an agent.
- Preserve `results/`, `legacy/`, and verification reports and their supporting
  evidence wherever they are stored. Do not delete, overwrite, or relocate
  them as part of routine cleanup. Such changes need an explicit request.
- Store new private verification reports, comparison data, and the scripts
  needed to reproduce internal checks in `local/internal_checks/<task-id>/`,
  unless the task specifies another private location. Retain the evidence
  needed to diagnose an unresolved failure.
- Keep manuscripts and `.tex` files local and out of Git. Do not publish
  private checks or archives by changing ignore rules or force-adding files.
- An untracked or ignored file is not necessarily disposable. Age, filename,
  or a `tmp`, `old`, or `test` prefix is not sufficient evidence for deletion.

### Safe cleanup before finishing

- Remove only files you created as disposable for the current task, after
  they are no longer needed and no running process uses them. Do not stop
  unrelated processes to enable cleanup.
- Before deleting scratch files, verify their resolved absolute paths stay
  inside this task's scratch directory. Do not traverse symlinks or Windows
  junctions to targets outside it. Use exact paths, not broad deletion globs.
- Remove temporary debugging code you introduced, but preserve pre-existing
  diagnostics and permanent tests or logging required by the task.
- Never use repository-wide cleanup, `git clean -fdx`, or destructive Git
  resets to satisfy these rules. Do not recursively clear `local/`, `tmp/`,
  `results/`, `legacy/`, or a shared system temporary directory.
- If ownership, purpose, or dependencies are uncertain, leave the file in
  place and ask before deleting or moving it. Cleaning older artifacts
  requires a separately agreed list of targets.
- Review the final diff and newly created files. Do not revert unrelated work
  just to obtain a clean Git status. If Git is unavailable, say so rather
  than treating files as safe to remove.
- In the final response, briefly report what temporary materials were removed
  and what was intentionally retained, with locations and reasons. If nothing
  needed removal, say so. Report cleanup failures without broadening deletion
  scope, and explain whether any material that was removed is recoverable.
